# Evolve UI Process - My Understanding Summary

**Date**: 2026-01-18

---

## What You Want

A **methodical, step-by-step UI development process** that:
1. **Scans chat context** to understand what was actually done
2. **Creates design document** (checked 3 times for accuracy)
3. **Builds technical requirements** from design
4. **Creates wireframe/boilerplate** (HTML structure only)
5. **Iteratively develops** component-by-component:
   - HTML boilerplate → Screenshot
   - Nav (empty) → Screenshot
   - Each element added one by one → Screenshot each step
6. **Uses WAFT tools** to answer questions during development
7. **Creates case files** as proof for each major decision
8. **Includes case files component** in the page itself
9. **Builds supporting materials** (dev profiles, CVs, work efforts, Pantheon)
10. **Saves screenshots** to `_work_efforts/`
11. **Project structure**: `_work_efforts/`, `README.md`, `index.html` at root

---

## Critical Rules

- **NO SKIPPING STEPS** - Must go sequentially
- **NO CODE DUMPING** - Build one component at a time
- **SCREENSHOT EVERY STEP** - Visual proof
- **CHECK DESIGN DOC 3X** - Verify before proceeding
- **CASE FILES FOR PROOF** - Document decisions
- **USE WAFT TOOLS** - Answer questions iteratively

---

## The Process

### Phase 1: Analysis & Design (MANDATORY)
1. Scan chat → Extract what was done
2. Create design doc → Describe purpose and goals
3. Check design doc → First check
4. Check design doc → Second check  
5. Check design doc → Third check
6. **ONLY THEN** proceed to requirements

### Phase 2: Requirements & Wireframe
7. Create technical requirements
8. Create wireframe (boxes only, no content)

### Phase 3: Iterative Development
9. HTML boilerplate → Screenshot
10. Nav (empty) → Screenshot
11. Add header → Screenshot
12. Add sidebar → Screenshot
13. Add main → Screenshot
14. Add footer → Screenshot
15. Add content to each section → Screenshot each
16. Use WAFT tools when stuck
17. Create case files for decisions
18. Include case files component

### Phase 4: Supporting Materials
19. Statement of purpose
20. Developer profiles
21. LaTeX CVs
22. Work effort tracking
23. Pantheon integration

---

**This is about METHODICAL, PROVEN development - not throwing code at the wall.**
