## 🔴 CRITICAL: Security Vulnerabilities

### 1. Scanner Can Read Sensitive Files (CRITICAL)
**Issue**: Plan states "Scan all `.py` files in `src/`" but provides NO exclusion list for sensitive files.
**Attack Vector**:
- Scanner could read `.env`, `secrets/`, `*.key`, `*.pem`, `*.p12`, `*.jks` files if they have `.py` extension or are in `src/`
- Could read files with secrets in comments: `# API_KEY=secret123`
- Could read git history if `.git/` is accessible
- Could read backup files: `*.py.bak`, `*.py~`, `*.py.swp`

**Impact**:
- Secrets exposed in debt reports (PDF output)
- Secrets logged in scan metadata
- Secrets stored in genome registry (JSON files)
- Information disclosure to unauthorized users

**Severity**: CRITICAL
**Fix Required**:
- Add explicit exclusion list: `.env`, `secrets/`, `*.key`, `*.pem`, `*.p12`, `*.jks`, `.git/`, `*.bak`, `*.swp`, `*.pyc`, `__pycache__/`
- Validate file paths before reading
- Never scan files outside project root (path traversal protection)
- Sanitize file paths in all output (reports, logs, registry)
- Add content filtering to exclude files with suspicious patterns (API keys, passwords)

### 2. Command Injection via `ruff check` (CRITICAL)
**Issue**: Plan mentions "Use `ruff check --select F401`" but provides NO details on how to safely execute this.
**Attack Vector**:
- If file paths contain shell metacharacters (`;`, `|`, `&`, `$`, `` ` ``, `\n`), command injection possible
- If `ruff` binary path is user-controlled, path injection possible
- If `--select` value is user-controlled, option injection possible

**Impact**: Arbitrary code execution as the user running the scanner
**Severity**: CRITICAL
**Fix Required**:
- **NEVER** use `subprocess.run(..., shell=True)` - this is a CRITICAL vulnerability
- Use `subprocess.run([...], shell=False)` with list of arguments
- Validate and sanitize ALL inputs to subprocess calls
- Use `shlex.quote()` if shell is absolutely necessary (but prefer avoiding shell)
- Validate file paths don't contain shell metacharacters
- Use absolute paths for `ruff` binary (don't trust PATH)
- Validate `--select` values against whitelist

### 3. Path Traversal Vulnerability (CRITICAL)
**Issue**: Plan says "Scan all `.py` files in `src/`" but doesn't validate paths.
**Attack Vector**:
- If `src/` contains symlinks pointing outside project: `src/../../etc/passwd`
- If file paths contain `../`: `src/../.env`
- If absolute paths are used: `/etc/passwd`
- If registry paths are user-controlled: `_genetics/../../.env`

**Impact**:
- Reading files outside project directory
- Information disclosure
- Potential secrets exposure

**Severity**: CRITICAL
**Fix Required**:
- Validate all file paths, reject paths with `..`
- Resolve symlinks and check they're within project root
- Reject absolute paths outside project root
- Use `Path.resolve()` and check against project root
- Add path validation to registry operations

### 4. Registry Files World-Readable (CRITICAL)
**Issue**: Plan stores genomes in `_genetics/tech_debt/scans/` with NO mention of file permissions.
**Attack Vector**:
- Default file permissions (0644) allow other users to read
- If project is on shared filesystem, other users can read debt data
- If project is in web-accessible directory, files could be exposed via web server misconfiguration

**Impact**:
- Information disclosure (debt items, file paths, code snippets)
- Potential secrets if debt items contain sensitive information
- Privacy violation (exposes codebase structure)

**Severity**: CRITICAL
**Fix Required**:
- Set restrictive file permissions: `0600` for files, `0700` for directories
- Use `os.chmod()` or `Path.chmod()` after file creation
- Validate registry location is within project (path traversal protection)
- Never store sensitive data in registry (sanitize before storage)
- Add access control checks (who can read/write registry)

### 5. No Input Validation on File Paths (CRITICAL)
**Issue**: Plan doesn't mention ANY input validation for file paths from scanner.
**Attack Vector**:
- Malicious file names with control characters
- File names with newlines (log injection)
- File names with path separators (path traversal)
- Extremely long file names (DoS)

**Impact**:
- Path traversal attacks
- Log injection attacks
- DoS attacks (resource exhaustion)

**Severity**: CRITICAL
**Fix Required**:
- Validate all file paths before use
- Reject paths with `..`, absolute paths outside project
- Sanitize file names (remove control characters, limit length)
- Validate path encoding (UTF-8, handle encoding errors)
- Add path length limits (prevent DoS)
