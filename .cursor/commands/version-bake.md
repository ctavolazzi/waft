# Version-Bake

**Complete quality workflow: reflect → run-it → improve → check-assumptions → verify → hypothesis → prove-it**

Bake quality into your version through systematic reflection, analysis, improvements, validation, verification, hypothesis formation, and scientific proof. Tracks the genetic lineage of ideas - the DNA of thoughts from Source outward and back again.

**Use when:** Completing significant work, need comprehensive quality assurance, want systematic verification, need evidence-based validation, or want to track the genetic lineage of your ideas.

---

## Purpose

This command provides:
- **Reflection**: Deep reflection on current work and learnings
- **Systematic Analysis**: Complete /run-it workflow with all phases
- **Improvement Identification**: Prioritized improvement recommendations
- **Assumption Validation**: Evidence-based assumption checking
- **Comprehensive Verification**: Multiple verification points
- **Hypothesis Formation**: Testable hypothesis development
- **Scientific Proof**: Demonstration of scientific method functionality
- **Complete Documentation**: All findings documented in work effort

---

## Philosophy

### 1. Quality Through Systematic Process

The workflow ensures quality through:
- **Reflection First**: Understand what you've done before analyzing
- **Systematic Analysis**: Complete /run-it workflow for thoroughness
- **Improvement Focus**: Identify and prioritize improvements
- **Assumption Checking**: Validate beliefs before proceeding
- **Evidence-Based**: All conclusions supported by evidence
- **Scientific Rigor**: Hypothesis formation and proof
- **Genetic Lineage**: Track the DNA of ideas from Source outward and back again

### 2. Self-Correcting Loop

If `/prove-it` fails:
1. Run `/check-assumptions` to identify issues
2. Fix problems
3. Retry `/prove-it`
4. Document learnings

This creates a feedback loop that ensures quality.

### 3. Complete Documentation

All phases generate documentation:
- Reflection entries in journal
- Analysis documents from /run-it
- Improvement reports
- Assumption validation reports
- Verification traces
- Hypothesis documents
- Proof results

Everything is saved to the current work effort.

## Execution Steps

### Step 1: Reflection

**Command**: `/reflect`

**Purpose**: Deep reflection on current work

**Actions**:
1. Check for journal (create if missing)
2. Write comprehensive reflection entry
3. Capture thoughts, learnings, patterns
4. Document what worked and what didn't

**Output**: Journal entry in `_pyrite/journal/ai-journal.md`

---

### Step 2: Complete /run-it Workflow

**Command**: `/run-it`

**Purpose**: Execute complete systematic workflow

**Phases** (15 total):
1. `/consider` - Options analysis
2. `/think` - Cognitive initialization
3. `/check-assumptions` - Assumption validation
4. `/deep-analyze` - Code analysis
5. `/critique` - Adversarial review
6. `/status` - Quick status
7. `/hypothesis` - Hypothesis formation
8. `/prove-it` - Scientific method proof
9. `/verify` - Comprehensive verification
10. `/proceed` - Final verification
11. `/reflect` - Final reflection
12. `/checkpoint` - Status checkpoint
13. `/decide` - Decision-making
14. `/next` - Next step identification
15. `/goal` - Goal tracking

**Output**: Multiple documents from each phase

---

### Step 3: Improvement Analysis

**Command**: `/improve`

**Purpose**: Identify and prioritize improvements

**Focus**: Current work (file, work effort, or all)

**Actions**:
1. Analyze code quality
2. Analyze documentation
3. Analyze architecture
4. Analyze testing
5. Analyze performance
6. Analyze usability
7. Generate prioritized recommendations

**Output**: Improvement report with scores and priorities

---

### Step 4: Assumption Checking

**Command**: `/check-assumptions`

**Purpose**: Validate all assumptions with evidence

**Actions**:
1. Extract assumptions from conversation
2. Categorize by type and risk
3. Gather validation evidence
4. Validate each assumption
5. Generate validation report

**Output**: Assumption validation report with evidence traces

---

### Step 5: Verification

**Command**: `/verify`

**Purpose**: Verify all claims and information

**Actions**:
1. Identify verifiable claims
2. Run verification checks
3. Document evidence traces
4. Generate verification report

**Output**: Verification traces and summary

---

### Step 6: Hypothesis Formation

**Command**: `/hypothesis`

**Purpose**: Form testable hypotheses

**Actions**:
1. Review findings from previous phases
2. Formulate testable hypotheses
3. Identify evidence
4. Define verification plan
5. Assess confidence

**Output**: Hypothesis document with structure

---

### Step 7: Prove Scientific Method

**Command**: `/prove-it`

**Purpose**: Demonstrate scientific method tool works

**Actions**:
1. Run simple proof demonstration
2. Run real experiment proof
3. Show state capture (A & B)
4. Show data collection (C)
5. Display analysis results
6. Verify file persistence

**Output**: Proof demonstration results

**If Fails**:
1. Run `/check-assumptions` to identify issues
2. Fix problems
3. Retry `/prove-it`
4. Document learnings

---

### Step 8: Documentation & Genetic Lineage

**Purpose**: Save all findings to work effort and track genetic lineage

**Actions**:
1. Identify current work effort
2. Create comprehensive workflow analysis document
3. Save improvement analysis
4. Save assumption validation
5. Save verification traces
6. Save hypotheses
7. Save proof results
8. **Track Genetic Lineage**: Document the DNA of ideas - chain of thoughts from Source outward and back again
9. Update work effort index

**Output**: All documentation in work effort directory, including genetic lineage tracking

## Error Handling

### If /prove-it Fails

1. **Document Failure**:
   - Note which step failed
   - Document error message
   - Capture context

2. **Run /check-assumptions**:
   - Identify assumptions that may have caused failure
   - Validate critical assumptions
   - Find root cause

3. **Fix Issues**:
   - Address identified problems
   - Update code/documentation
   - Verify fixes

4. **Retry /prove-it**:
   - Run proof again
   - Verify success
   - Document resolution

5. **Continue Workflow**:
   - Complete remaining documentation
   - Update work effort
   - Note what was learned
