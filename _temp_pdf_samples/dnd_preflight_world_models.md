## The Architecture: V-M-C for D&D

The World Models paper presents a simple model inspired by our cognitive system:

```
┌─────────────────────────────────────────────────────────┐
│                    V-M-C Architecture                    │
│                                                          │
│  ┌──────────┐      ┌──────────┐      ┌──────────┐     │
│  │    V     │      │    M     │      │    C     │     │
│  │ (Vision) │ ───> │ (Memory) │ ───> │(Control) │     │
│  └──────────┘      └──────────┘      └──────────┘     │
│       │                 │                 │            │
│  Compresses        Predicts          Decides           │
│  what agent        future            actions           │
│  sees              states                              │
└─────────────────────────────────────────────────────────┘
```

### Our D&D World Model

<div style="background: #f9f9f9; padding: 1.5em; margin: 1.5em 0; border-radius: 5px;">

**V (Vision) → Campaign State Encoder**
- Compresses game state (location, NPCs, items, story beats)
- Encodes current situation into compact representation
- **"What the Being sees"** in the D&D world

</div>

<div style="background: #f9f9f9; padding: 1.5em; margin: 1.5em 0; border-radius: 5px;">

**M (Memory) → Campaign Predictor (MDN-RNN-like)**
- Predicts future game states based on Being's actions
- Models probability distribution of next states
- **"What will happen next"** in the campaign

</div>

<div style="background: #f9f9f9; padding: 1.5em; margin: 1.5em 0; border-radius: 5px;">

**C (Controller) → Being Decision System**
- Decides actions based on V and M representations
- Maximizes expected campaign success (survival, story progression)
- **"What the Being chooses to do"**

</div>

<div style="background: #fff9e6; padding: 1.5em; margin: 2em 0; border-left: 4px solid #ffd700;">

**The Key Insight**: Just as World Models trains agents in their own "dreams" (hallucinated environments), we train Beings in their own D&D "dreams" (generated campaign narratives).

</div>

## Training in the Dream

From World Models:

> "We can ask [the world model] to produce the probability distribution of z_{t+1} given the current states, sample a z_{t+1} and use this sample as the real observation. We can put our trained C back into this hallucinated environment generated by M."

### Our D&D Training Process

```
┌─────────────────────────────────────────────────────┐
│            Training in the Dream                    │
│                                                     │
│  1. Collect Rollouts                                │
│     └─> Run campaigns with exploratory behavior    │
│                                                     │
│  2. Train V (Vision)                                │
│     └─> Learn to encode campaign states             │
│                                                     │
│  3. Train M (Memory)                                │
│     └─> Learn to predict next campaign states       │
│                                                     │
│  4. Train C (Controller)                            │
│     └─> Being learns optimal actions in dream       │
│                                                     │
│  5. Transfer to Reality                             │
│     └─> Being's learned policy works in campaigns   │
└─────────────────────────────────────────────────────┘
```

The Being trains entirely in the **latent space** of the campaign - not in pixel frames, but in narrative states, story beats, and game mechanics.

## The World Model Components

### V: Campaign State Encoder

**Purpose**: Compress the current campaign state into a compact representation

**What it encodes**:
- Current location (tavern, forest, mountain, dragon's lair)
- Active NPCs and their states
- Being's current stats (HP, skills, inventory)
- Story progression (which beats have occurred)
- Campaign arc position (Act 1, 2, 3, Conclusion)

**Output**: Compact state vector `z_t` that captures the essence of the current situation

---

### M: Campaign Predictor (MDN-RNN-like)

**Purpose**: Predict future campaign states based on Being's actions

**What it models**:
- `P(z_{t+1} | a_t, z_t, h_t)` - Probability of next state given action, current state, and hidden memory
- Story progression probabilities
- NPC reaction probabilities
- Combat outcome probabilities
- Campaign conclusion probabilities

**Key Feature**: Models **stochastic** campaign outcomes - not deterministic, but probabilistic. The campaign has uncertainty, randomness, and multiple possible futures.

---

### C: Being Controller

**Purpose**: Decide actions that maximize campaign success

**Input**: `[z_t, h_t]` - Current state representation + memory hidden state

**Output**: Action `a_t` - Being's decision (explore, talk, fight, rest, etc.)

**Training**: Evolve Being's decision-making to maximize:
- Campaign survival (don't die)
- Story progression (reach conclusion)
- Being evolution (skills, fitness, memories)
- Narrative quality (interesting story)

**The Transfer**: After Being learns in DnDRNN, deploy to actual campaign with full narrative generation.

## Temperature and Uncertainty

From World Models:

> "We can adjust a temperature parameter τ to control model uncertainty... We find agents that perform well in higher temperature settings generally perform better in the normal setting."

### Our D&D Application

| Temperature | Characteristic | Outcome |
|------------|---------------|---------|
| **Low (τ = 0.1)** | Deterministic, predictable | Being might exploit model imperfections |
| **High (τ = 1.15-1.30)** | Stochastic, uncertain | Being learns robust strategies |

**The Balance**: Train Being in challenging dream environment (higher temperature), then deploy to actual campaign (normal temperature) for better performance.

## Iterative Training Procedure

From World Models:

```
1. Initialize M, C with random parameters
2. Rollout to actual environment N times, save observations
3. Train M to model P(x_{t+1} | x_t, a_t, h_t) and train C inside M
4. Go back to (2) if task not completed
```

### Our D&D Version

│                 │                                   │
│                 ▼                                   │
